# ТЗ «Консильери»: робот MT5 + ИИ-ассистент в Telegram — всё в одном

31.10.2026 · для Claude Code

> Это единственное ТЗ проекта. Всё прошлое — ТЗ этапа 1, ТЗ ассистента, кнопочный бот `tg_bot` — отменено. Делать заново, в одной папке `consigliere-trading-/`, по разделу 18.

## 1. Цель и рамки

«Консильери» — ИИ-ассистент по трейдингу на отдельном аккаунте Telegram. Абу пишет ему или звонит, ассистент отвечает текстом и голосом, даёт зоны BUY и SELL по стратегии Mr. Casino и книге, ведёт робота и сам звонит при тревоге. Всё работает на игровом ПК Абу рядом с MT5. Это единственное ТЗ проекта: робот, мост и ассистент описаны здесь целиком.

**Входит:**

- Робот MT5 v3.3: файловый мост, события, команды, тревоги, скрины (разделы 5–8).
- Отдельный Telegram-аккаунт ассистента (userbot), общается только с Абу.
- Диалог обычным текстом и голосовыми сообщениями, без кнопок и команд.
- Голосовые звонки Telegram: Абу звонит ассистенту; ассистент звонит Абу при критичной тревоге.
- Анализ графика и зоны BUY/SELL по просьбе («дай зону») — с работающим роботом и без него.
- Робот: статус, сделки, статистика, управление после «да», тревоги, утренний план, дневной и недельный отчёт.
- Одна папка `consigliere-trading-/` (раздел 3): робот + ассистент + документы; установка и автозапуск на Windows.

**Не входит:** разговоры не про трейдинг; доступ ко всему ПК (только MT5, робот и его файлы); сделки по решению самого ИИ без «да»; платные телефонные звонки (Twilio); изменение торговой логики робота.

**Главные правила:**

1. Ассистент слушает только один Telegram ID — Абу. Всех остальных игнорирует.
2. Любое действие, которое что-то меняет, выполняется только после «да» Абу; это проверяет код, а не ИИ. Исключение одно: пауза робота при аварии.
3. Цифры ассистент берёт только из инструментов (MT5, робот, движок анализа) и никогда не выдумывает.
4. Робот торгует и без ассистента: падение ассистента или конец бюджета API не ломает торговлю и защиту (стоп, тейк, дневной лимит).
5. Зоны и анализ — мнение по правилам стратегии, а не гарантия; решение входить остаётся за Абу.

## 4. Архитектура

На ПК работают два процесса: MT5 с роботом и Python-ассистент. Ассистент читает цены напрямую из MT5, управляет роботом через файловый мост и выходит в интернет только к Telegram, Claude API и сервису озвучки.

```text
   iPhone Абу  <── текст, голосовые, звонки ──>  Telegram  <── MTProto ──>  Ассистент (ПК)
                                                                             │
   Claude API (мозг, анализ скринов)  <───────────────────────────────────┤
   edge-tts (голос ассистента)  <──────────────────────────────────────┤
                                                                             │
   ПК Абу:  MT5 + робот v3.3  <── пакет MetaTrader5 (цены, счёт) ────────┤
                     │                                                       │
                     └── папка моста: status, events, cmd, trades, shots ──┘
```

**Части ассистента:**

| Часть | Что делает | Чем |
| --- | --- | --- |
| Telegram-клиент | входит как обычный аккаунт, получает и шлёт сообщения | Pyrogram-форк или Telethon (выбор по совместимости со звонками) |
| Звонки | принимает и делает голосовые звонки 1:1 | `py-tgcalls` + ffmpeg |
| Уши | голос → текст, конец фразы | `faster-whisper` (локально), `silero-vad` |
| Мозг | понимает запрос, вызывает инструменты, отвечает | Claude API с инструментами (tool use) |
| Голос | текст → речь | `edge-tts`, голос `ru-RU-DmitryNeural` |
| Данные рынка | свечи W1–M5, счёт, позиции, история | пакет `MetaTrader5` (только чтение) |
| Движок анализа | зоны по правилам Mr. Casino и книги, картинка графика | Python-порт логики робота, pandas, mplfinance |
| Мост | статус и события робота, команды роботу | контракт из раздела 6 |
| Сторож и расписание | тревоги, утренний план, отчёты | asyncio-задачи, psutil |
| Хранилище | короткая память диалога, ожидающие «да», тревоги, журнал, расход API | SQLite |

Управление сделками идёт только через робота (один исполнитель, его лимиты и защита). Пакет `MetaTrader5` закрывает позицию напрямую только в аварии: робот не отвечает, а Абу сказал «да».

## 5. Робот MT5 v3.3

Робот v3.3 получает мост, таймер, команды и тревоги; входы, стопы, тейки и фильтры v3.2 не меняются. `#property version "3.30"`, на панели — «v3.3».

### 5.1 Новые входные параметры (группа «Telegram-бот (мост)»)

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `InpBridge` | true | вести файловый мост |
| `InpBridgeKey` | "" | секрет команд; пусто = команды не принимаются, в журнал и на панель — предупреждение |
| `InpStatusSec` | 10 | как часто обновлять `status.json`, секунд |
| `InpShots` | true | скрины графика к входу, выходу, отчёту, брифингу и по команде |
| `InpShotW`, `InpShotH` | 1280, 720 | размер скрина, пикселей |
| `InpMorningHM` | "09:30" | утренний брифинг, время Бишкека (пусто = выкл.) |
| `InpReportHM` | "23:05" | дневной отчёт, время Бишкека (пусто = выкл.) |
| `InpTgFallback` | true | бот молчит дольше 3 минут — критичные события идут напрямую через `WebRequest` (нужны `InpTgToken`, `InpTgChatId` и разрешённый URL) |
| `InpAlertDDPct` | 3.0 | тревога: эквити ниже баланса начала дня на N% |
| `InpAlertSpreadX` | 3.0 | тревога: спред больше N × `InpMaxSpreadPt` дольше 2 минут при открытой позиции |

При работающем боте `InpTgToken` и `InpTgChatId` нужны только для запасного канала: в обычном режиме робот в Telegram не пишет, чтобы не было дублей.

### 5.2 Таймер

- `EventSetTimer(1)` в `OnInit`, `EventKillTimer()` в `OnDeinit`. `OnTimer` работает и без тиков (выходные, тихий рынок), поэтому команды и статус идут через него.
- Каждую секунду: проверить папку `cmd` (`FileFindFirst` с `FILE_COMMON`), выполнить команды по порядку `ts_utc`.
- Каждые `InpStatusSec`: записать `status.json`, прочитать `bot_heartbeat.json`.
- Каждые 5 с: проверить условия тревог (5.8).
- По времени Бишкека: утренний брифинг и дневной отчёт, один раз в день (дата последней отправки хранится в `settings.json`). В субботу и воскресенье брифинг не шлётся.

### 5.3 События вместо прямого Telegram

- Новая функция `Emit(type, level, severity, dataJson, text)`: пишет событие в `events`, обновляет `status.json`, оставляет Push MT5 как сейчас. `Notify()` вызывает `Emit()`.
- Прямая отправка `SendTG()` — только в запасном режиме и только для `severity = critical` и `trade_opened` / `trade_closed`; при переходе в этот режим — одно сообщение «бот не отвечает, пишу напрямую».
- Небольшой JSON-помощник на MQL5: сборка объектов строкой с экранированием `"`, `\`, переводов строки; числа — через `DoubleToString` с точкой; разбор команд — простой парсер плоского JSON (строки, числа, true/false) и одного вложенного `args`.
- Список событий, уровни и поля — раздел 7.

### 5.4 Настройки, меняющиеся из Telegram

- Входные параметры MQL5 — константы, поэтому ввести структуру `g_set`: `paused`, `riskPct`, `dailyRiskPct`, `maxTrades`, `rr`, `weak`, `tradeBuy`, `tradeSell`. В `OnInit` заполнить из входных параметров, затем наложить `settings.json`.
- Заменить чтение этих параметров на `g_set` везде: `Relaxed`, `GlobalBlock`, `TradeRiskPct`, `DailyRiskLeft`, `CalcLot`, `TryEntry` (тейк RR, стороны), `RebuildZones` (стороны), `OnPositionClosed`, `DrawPanel`, сообщения `OnInit`.
- Команда `reset` удаляет изменения и возвращает значения входных параметров. На панели изменённые из Telegram значения помечены «(TG)».

### 5.5 Пауза и автопауза

- Пауза останавливает только новые входы: `GlobalBlock` возвращает «пауза (Telegram)». Открытая позиция сопровождается как обычно: безубыток, ранний выход, закрытие в пятницу.
- Автопауза + критичная тревога: 3 отклонённых ордера подряд; позиция робота без стопа, которую не удалось исправить за 3 попытки. Снимается только командой `resume`.

### 5.6 События анализа

- `zone_touch`: цена впервые зашла в торгуемую зону CONFIRMED (флаг в `SZone`, один раз на зону).
- `signal_skipped`: триггер был (`EvalZone` = true), но вход заблокировал фильтр: балл, COUNTER, FVG, Doji / волчок, импульс, стоп больше максимума, RR, лот и риск, спред, новости, лимиты, пауза. Для этого `Skip(zi, why)` получает третий аргумент `hadSignal`. Повтор той же причины по той же зоне — не чаще раза в 30 минут (как сейчас).
- Пропуски без триггера («нет триггера») — событие `analysis_skip` уровня 2.
- `bias_changed` при смене D1 или H4; `zone_invalid` с причиной (уровень 2).

### 5.7 Скрины графика

- Когда: вход и выход (после отрисовки линий SL/TP), дневной отчёт, утренний брифинг, команда `chart`.
- M5 — график робота с зонами: `ChartRedraw()`, `ChartScreenShot(0, "MrCasino_shot.png", InpShotW, InpShotH, ALIGN_RIGHT)`, затем `FileMove("MrCasino_shot.png", 0, "MrCasino\\<robot>\\shots\\<seq>.png", FILE_COMMON | FILE_REWRITE)`.
- M15, H1, H4 — временный график `ChartOpen(sym, tf)`, на него копируются прямоугольники зон, скрин, `ChartClose`.
- Скрин не получился — событие уходит без фото, в `data.shot` пусто.

### 5.8 Тревоги, которые видит робот

Событие `alert` с полями `key` (ключ для склейки), `state` (`open` или `closed`), `severity` (`warning` или `critical`). Каждое состояние шлётся один раз при начале и один раз при окончании.

| key | Условие | Важность |
| --- | --- | --- |
| `disconnect` | `TERMINAL_CONNECTED` = false дольше 60 с | critical |
| `algo_off` | `TERMINAL_TRADE_ALLOWED` или `MQL_TRADE_ALLOWED` = false | critical |
| `no_sl` | позиция робота без стопа; робот пытается поставить стоп заново | critical |
| `orders_rejected` | 3 отказа подряд → автопауза; одиночный отказ — `order_rejected`, warning | critical |
| `equity_stop` | v3.4: эквити ниже `InpEquityStopUSD`: позиция закрыта, робот на паузе; пауза снимается командой `resume` только когда эквити выше порога | critical |
| `day_dd` | эквити ниже баланса начала дня на `InpAlertDDPct` | warning |
| `day_limit` | дневной риск исчерпан, робот стоит до завтра | critical |
| `spread` | спред выше нормы в `InpAlertSpreadX` раз дольше 2 минут при открытой позиции | warning |
| `no_ticks` | нет тиков 5 минут, а торговая сессия символа открыта (`SymbolInfoSessionTrade`) | warning |
| `margin` | уровень маржи ниже 200% | warning |
| `friday_close` | позиция закрыта перед выходными | info |

### 5.9 Запуск, остановка, сделки

- `ea_started`: версия, счёт, символ, действующие настройки. `ea_stopped`: причина из `OnDeinit(reason)` по-русски (снят с графика, перекомпиляция, смена счёта, закрытие терминала и т.д.). Падение терминала события не даёт — его ловит сторож бота.
- Робот пишет закрытые сделки и в старый `MrCasino_v32_trades.csv`, и в `trades.csv` моста (новые колонки — раздел 13).
- Ручные сделки по команде `open` открываются с magic робота и комментарием `MC MANUAL`: робот ведёт их как свои (безубыток, пятница), в статистике они помечены `manual`.
- Панель: строка «Бот: онлайн / нет связи N мин» и «ПАУЗА (Telegram)», когда пауза включена.
- В `OnTick` — никаких `Sleep` и сетевых запросов; запись файлов — только при событиях и по таймеру.

## 6. Файловый мост

«Бот» в этом разделе = ассистент.

Робот и бот обмениваются только файлами в общей папке MT5; сети между ними нет. Корень: `%APPDATA%\MetaQuotes\Terminal\Common\Files\MrCasino\<login>_<magic>\` (в MQL5 — флаг `FILE_COMMON`, путь `MrCasino\\<login>_<magic>\\...`). Одна папка на каждый запущенный робот: демо и реальный счёт на одном ПК не путаются.

| Файл | Пишет | Читает | Зачем | Как пишется |
| --- | --- | --- | --- | --- |
| `status.json` | робот | бот | текущее состояние; каждые 10 с и после каждого события | `status.tmp`, затем `FileMove` с `FILE_REWRITE` (атомарно) |
| `events\YYYYMMDD.jsonl` | робот | бот | лента событий, одна строка JSON на событие, файл на день по Бишкеку | дозапись в конец |
| `cmd\<id>.json` | бот | робот | одна команда = один файл | бот пишет `<id>.tmp` и переименовывает в `.json`; робот выполняет и удаляет |
| `settings.json` | робот | робот, бот | настройки, изменённые из Telegram, и счётчик `seq`; переживают перезапуск | атомарно |
| `trades.csv` | робот | бот | закрытые сделки (колонки — раздел 13) | дозапись |
| `shots\<seq>.png` | робот | бот | скрин графика к событию | `ChartScreenShot` в `MQL5\Files`, затем `FileMove` в общую папку |
| `bot_heartbeat.json` | бот | робот | бот жив: время последнего цикла, каждые 10 с | атомарно |

**Правила формата:**

- Кодировка UTF-8 без BOM. В MQL5 писать через `FILE_BIN` + `StringToCharArray(..., CP_UTF8)`: режим `FILE_TXT | FILE_ANSI` портит русский текст.
- У каждого события и статуса есть `ts_utc` (ISO 8601 с Z) и `ts_local` (Бишкек).
- Событие: `{"seq":1532,"ts_utc":"...","ts_local":"...","type":"trade_opened","level":0,"severity":"info","robot":"<login>_<magic>","data":{...},"text":"готовый текст на русском"}`. `seq` растёт всегда и хранится в `settings.json`; `text` — запасной текст, если у бота нет шаблона на этот тип.
- Бот хранит курсор (файл, смещение в байтах, последний `seq`) в своей базе: после перезапуска не шлёт старое повторно; пропуск `seq` пишет в лог. Неполную последнюю строку (без `\n`) не читает, ждёт следующего цикла.
- При первом запуске бот начинает с конца текущего файла, а не с начала истории.
- Команда: `{"id":"<uuid>","cmd":"set_risk","args":{"pct":0.5},"ts_utc":"...","expires_utc":"<+60 с>","key":"<BRIDGE_KEY>"}`. Робот отвечает событием `cmd_result` с тем же `id`: `{"id":"...","ok":true,"msg":"риск 0.5% на сделку"}`.
- Хранение: события 30 дней, скрины 7 дней (чистит бот). Команду с истёкшим `expires_utc` робот не выполняет: удаляет и отвечает `ok:false, msg:"команда устарела"`.

## 9. Аккаунт ассистента в Telegram

Ассистент — обычный Telegram-аккаунт на отдельном номере, которым управляет программа через официальный Telegram API (MTProto). Бот из @BotFather так не умеет: звонить может только аккаунт.

**Настройка:**

1. Новая SIM O!, регистрация Telegram на любом телефоне. Имя «Консильери», аватарка на выбор Абу. Включить облачный пароль (2FA).
2. my.telegram.org → API development tools → `api_id` и `api_hash` для этого аккаунта.
3. Первый вход на ПК: `start_agent.bat --login` спрашивает код из Telegram и пароль 2FA, создаёт файл сессии. Дальше вход автоматический.
4. Абу добавляет ассистента в контакты, ставит для него отдельный звук и разрешает его звонки в режиме фокусировки iPhone (чтобы звонок при тревоге доходил и ночью).
5. SIM держать активной (пополнять): потеря номера = риск потерять аккаунт.

**Правила, чтобы Telegram не заблокировал аккаунт:**

- Пишет и звонит только `OWNER_ID`; никому другому не отвечает, чужие звонки отклоняет, в группы не вступает.
- Не чаще 1 сообщения в секунду, обработка `FloodWait` (ждать, сколько сказано).
- Работает с домашнего интернета ПК, одна сессия, без прокси.
- Чужие сообщения — в лог и одно уведомление Абу в сутки («писал незнакомый @…»).

Файл сессии — это ключ от аккаунта: только на ПК, в `.gitignore`, никому не передавать.

## 10. Мозг: Claude API и инструменты

Каждое сообщение Абу идёт в Claude вместе с инструкцией (характер, стратегия, книга), короткой историей диалога и сводкой состояния робота; факты Claude получает только через инструменты.

- **Две модели в конфиге:** `MODEL_FAST` — чат и звонки (быстрее и дешевле), `MODEL_SMART` — «дай зону», разбор сделок, недельный отчёт.
- **Кэш инструкции** (prompt caching): стратегия и книга большие, кэш сильно удешевляет повторные запросы.
- **Память диалога:** последние 20 сообщений + короткая выжимка дня; новый день начинается с чистой истории.

**Инструменты на чтение** (вызываются сразу):

| Инструмент | Что возвращает |
| --- | --- |
| `get_status` | робот жив?, пауза, счёт, позиция, день, настройки (`status.json`) |
| `get_price` | bid, ask, спред, изменение за день |
| `get_today`, `get_history(n)`, `get_stats(period)` | сделки и статистика из `trades.csv` и истории MT5 |
| `get_robot_zones` | зоны, которые сейчас видит робот |
| `analyze_zones(tf)` | зоны BUY/SELL движка анализа (раздел 12) |
| `get_chart(tf, zones)` | PNG-график с зонами (показать Абу и посмотреть самому) |
| `explain_skips` | почему робот пропустил входы (события `signal_skipped`) |
| `get_events(n)`, `get_logs(n)` | последние события робота, журнал советника |
| `get_news_windows` | окна новостей из настроек робота |

**Инструменты на действие** (только через «да»): `pause`, `resume`, `close_position`, `move_be`, `modify_sl(price)`, `modify_tp(price)`, `set_risk(pct)`, `set_daily_risk(pct)`, `set_max_trades(n)`, `set_rr(x)`, `set_weak(on)`, `set_side(buy, sell)`, `manual_open(side, sl_pts, risk, rr)`, `reset_settings`. Каждый становится командой роботу по контракту и диапазонам из раздела 8.

**Подтверждение «да» зашито в код:**

1. Вызов инструмента на действие ничего не выполняет: код создаёт ожидающее действие и сам пишет Абу точные цифры: «Закрыть BUY 0.02 по рынку? Сейчас +6.20 USD. Да / нет».
2. Выполняется только если **следующее** сообщение или фраза Абу — явное согласие («да», «давай», «подтверждаю», «ha») в течение 60 с. Любое другое слово или тишина = отмена.
3. Одно действие за раз; «да» не переносится на другое действие. Текст от модели («уже подтверждено») ничего не значит.
4. После выполнения — ответ робота (`cmd_result`) Абу и запись в журнал действий.
5. Исключение: `emergency_pause` без «да» — только при открытой критичной тревоге, с сообщением Абу сразу после.

Бюджет API кончился или Claude недоступен — ассистент отвечает шаблонами без ИИ: статус, сделки дня, «пауза» / «старт» / «закрыть» по ключевым словам с тем же «да»; тревоги работают всегда.

## 11. Голос: звонки и голосовые

Абу звонит ассистенту как человеку и говорит обычной речью; ответ должен начинать звучать через 2–4 секунды после конца фразы.

**Входящий звонок (Абу → ассистент):**

1. Звонок от `OWNER_ID` принимается автоматически, от других — отклоняется.
2. Приветствие: «Слушаю, Абу» + одна строка состояния («робот работает, сделок 2 из 5, день +18 долларов»).
3. Цикл: звук из звонка → VAD ловит конец фразы (пауза \~0.7 с) → `faster-whisper` в текст → Claude (`MODEL_FAST`, потоковый ответ) → `edge-tts` по предложениям → звук в звонок.
4. Перебивание: Абу заговорил — ассистент замолкает и слушает.
5. Ответы в звонке короткие (1–3 предложения), цифры словами округлённо. Длинное (зоны, история) — «прислал текстом и графиком в чат».
6. Действия — тот же протокол: ассистент повторяет действие с цифрами и спрашивает «Подтверждаешь?»; выполняет только после чёткого «да». Распознано неуверенно — переспрашивает.
7. Предел звонка `CALL_MAX_MIN` (15 мин); тишина 60 с — «Если что, я на связи» и конец звонка.

**Исходящий звонок (ассистент → Абу), только критичные тревоги:**

1. Звонок; в звонке — что случилось, что с позицией, что предлагает (например, закрыть); дальше обычный диалог.
2. Не ответил за 30 с — голосовое + текст в чат; повтор звонка через 2 минуты, до 5 раз, пока Абу не ответит, не напишет «принял» или причина не уйдёт.
3. Обычные сделки, отчёты, предупреждения — без звонка, текстом (голосовое по настройке).

**Голосовые сообщения:** голосовое Абу → текст (Whisper) → обычный диалог. На голосовое ассистент отвечает голосовым + коротким текстом, на текст — текстом. Это и запасной вариант, если звонки 1:1 не заработают (раздел 20).

**Техника:** звук звонка PCM 48 кГц через `py-tgcalls` и ffmpeg; Whisper модель `base` по умолчанию (`small` или `medium`, если хватает памяти и видеокарты), язык `ru`, на GPU (CUDA) или CPU int8; диск под модель до 2 ГБ. Озвученные частые фразы кэшируются.

## 12. Анализ и зоны «дай зону»

На «дай зону» (и похожее: «зоны», «анализ», «что по золоту», «где покупать», «зоны на завтра») ассистент за 30 секунд или быстрее присылает до 2 зон BUY и до 2 зон SELL с графиком. Работает и когда робот на паузе или выключен; нужен только запущенный MT5.

**Шаги анализа:**

1. **Данные.** Пакет `MetaTrader5`: свечи W1 (100), D1 (200), H4 (300), H1 (500), M15 (500), M5 (300) по символу золота из конфига или из статуса робота.
2. **Bias.** D1 и H4 по FU и Negation, как в роботе (`CalcBias`); тип зоны WITH / MIXED / COUNTER.
3. **Зоны по Mr. Casino** — Python-порт логики `MrCasino.mq5` с теми же параметрами, чтобы зоны совпадали с роботом:
   - Order Block на W1, D1, H4, H1 (стратегия: OB ищут от Weekly до 1H), зона = тела odd-свечей;
   - тени FU на H1 и M15 с классами A, B, C (SFU / AFU); HCS, включая x2/x3; Negation;
   - ликвидность: равные хаи/лои (идеальные двойные вершины и дна), swing, Doji (не AFU), трендовые линии с 3+ касаниями (новое, в роботе нет), major и minor;
   - HTF Re-test Levels на H4 (пара Doji + большая свеча с тенью, уровни 1–4);
   - имбаланс (FVG): зона внутри незакрытого FVG — штраф, разворот из имбаланса не берётся;
   - слияние источников, балл зоны и статус NEW / CONFIRMED как в роботе; ширина зоны 3–10 пунктов (Абу: идеально 5, максимум 10).
4. **Слой книги.** Свечные модели у зоны (молот, поглощение, утренняя/вечерняя звезда, 3 солдата/вороны, повешенный; Doji и волчок = ждать) и фигуры (двойная/тройная вершина, голова-плечи, клин, флаг, треугольник). По правилу Mr. Casino фигура = где стоят стопы толпы (цель и ликвидность), а не вход.
5. **План по каждой зоне.** Вход — только после манипуляции в зоне (FU, HCS, Negation, снятие ликвидности); стоп — True Stop за дальним краем зоны (5–15 пунктов); тейк — RR 1:2 и ближайшая LAL / major ликвидность; отмена — закрытие M15 за зоной или пробой Level #4.
6. **Картинка и взгляд ИИ.** `mplfinance` рисует H1 (или запрошенный ТФ) с прямоугольниками зон, уровнями ликвидности и текущей ценой. Картинка + данные движка идут в `MODEL_SMART`: он проверяет и объясняет простыми словами. ИИ не придумывает цифры зон: границы только из движка.
7. **Сверка с роботом.** Робот работает — его зоны сравниваются с движком; расхождение больше 1 пункта показывается с причиной.

**Формат ответа** (+ картинка графика):

```text

Времена — в конфиге.

**Сторож — проверки:**

| Проверка | Условие | Важность | Действие |
| --- | --- | --- | --- |
| MT5 закрыт | процесса `terminal64.exe` нет дольше 30 с | critical | автоперезапуск из `MT5_PATH`: не чаще 1 раза в 10 минут и 3 раз в час; о результате — сообщение |

## 14. Характер и правила

Инструкция ассистента лежит в `agent/brain/prompts/system.md` и состоит из трёх частей: характер и правила (ниже), `docs/strategy_mr_casino.md`, `docs/book_oddiy_savdo.md`.

- **Кто он:** «Консильери» — советник Абу по трейдингу: спокойный, скромный, честный. Обращается «Абу» или «брат», пишет по-русски просто и коротко. Понимает опечатки, простую речь, отдельные узбекские слова («ha» = да).
- **Только трейдинг:** золото и рынок, робот, стратегия Mr. Casino, книга, риск, психология трейдера (FOMO, серии убытков), брокеры и MT5. На другие темы — одна фраза: «Я только по трейдингу, брат».
- **Честность:** цифры только из инструментов; нет данных — так и говорит («MT5 не отвечает, не могу посмотреть»). Не обещает прибыль, не приукрашивает результаты, признаёт ошибки.
- **Риск:** если Абу поднимает риск выше дневного лимита или торгует после серии стопов — одно спокойное предупреждение с цифрами, дальше решает Абу. Без нравоучений.
- **Анализ:** всегда по правилам стратегии; фигуры и паттерны книги — как ликвидность (Main Retail Focus), вход только после манипуляции; в конце одна строка «решение за тобой».
- **Действия:** предлагает с точными цифрами и ждёт «да» (раздел 10); сам сделки не открывает.
- **Формат:** чат — до 6 строк, цифры с единицами (pt, USD), время по Бишкеку; звонок — 1–3 предложения; эмодзи только как метки (🟢 BUY, 🔴 SELL, 🚨 тревога).

## 15. Безопасность и стоимость

Ассистент видит и трогает только трейдинг: у модели нет доступа к командной строке, файлам ПК и интернету — только инструменты из раздела 10.

- Экономия: кэш инструкции; быстрая модель для чата и звонков; картинка графика в модель только для «дай зону» и разборов; события робота форматирует код по шаблонам, без ИИ; речь ↔ текст бесплатно (Whisper, edge-tts).
